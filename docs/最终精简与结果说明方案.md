# CWRU 最终精简与结果说明方案

## 1. 最终目标

本项目最终不是要做成一个正式软件，而是要满足下面三个要求：

1. 汇报时能够按照“读取数据 → 数据划分 → 信号处理 → 建立模型 → 训练 → 评价 → 汇总结果”的顺序讲清楚。
2. 最终代码与已经完成的 90 组实验结果能够一一对应，老师询问结果来源时有代码可以说明。
3. 删除与课程实验无关的工程化功能，例如复杂命令行、批次状态管理、断点续训和自动生成项目说明。

精简不能只追求文件少。如果删除后无法说明已有结果是怎样生成的，就属于过度精简。

## 2. 最终代码应当怎样组成

### 2.1 必须保留的实验核心

| 内容 | 当前所在位置 | 具体作用 | 汇报时怎样解释 | 建议 |
|---|---|---|---|---|
| 项目参数表 | `cwru/config.py` | 集中记录数据路径、四个故障类别、窗口长度、两种窗口步长、五种输入方案、三个模型名称和训练超参数 | “所有实验使用同一套参数，避免不同模型之间训练条件不一致。” | 保留，但删除批次管理和临时目录等不再使用的参数 |
| 数据文件识别 | `cwru/data/audit.py` | 根据 MAT 文件名识别正常、内圈、外圈、滚动体故障，读取故障直径、负载和测量端，并处理三个特殊文件的变量名称 | “先把 109 个原始文件整理成统一的文件信息，后续代码不用逐个手工判断。” | 保留 |
| 振动信号读取 | `cwru/data/signals.py` | 从 MAT 文件中读取 DE 或 FE 振动信号；把正常数据从 48 kHz 降采样到 12 kHz；把长信号切成长度 1024 的窗口 | “所有数据统一到 12 kHz，然后按 1024 点切成神经网络输入。” | 保留 |
| 数据划分读取 | `cwru/data/split.py` | 读取 `splits/A`、`splits/B`、`splits/C` 中已经固定的训练、验证和测试文件名单 | “先按完整文件划分，再在每个集合内部切窗口，所以同一个原始文件不会同时出现在训练集和测试集。” | 保留，但大幅缩短，只保留 JSON 读取和简单的集合检查 |
| 神经网络输入构建 | `cwru/data/dataset.py` | 根据输入方案选择 DE、FE 或双通道；创建分类标签和直径标签；只使用训练集计算均值、标准差和类别权重；转换为 PyTorch Dataset | “训练、验证、测试共用训练集算出的标准化参数，避免提前看到测试集信息。” | 保留，删除不再使用的实验清单生成逻辑 |
| 三个模型结构 | `cwru/models/models.py` | 定义一维 CNN、CNN-GRU 和 CNN-LSTM；三个模型都输出四分类结果和故障直径 | “三个模型使用相同 CNN 主干，区别是是否使用 GRU 或 LSTM 学习时间关系。” | 保留 |
| 模型训练过程 | `cwru/training/trainer.py` | 分批训练模型；计算分类损失和故障直径损失；在验证集上选择最佳模型；执行学习率调整和早停；保存最佳权重和训练历史 | “训练集负责更新参数，验证集负责选择最佳 epoch，测试集不参与模型选择。” | 保留 |
| 指标计算 | `cwru/evaluation/metrics.py` | 计算 Accuracy、Macro-F1、混淆矩阵、各类别指标、故障直径 MAE/RMSE、文件级预测和细分结果 | “分类看 Accuracy 和 Macro-F1，直径预测看 MAE 和 RMSE，同时统计窗口级和文件级结果。” | 保留 |
| 单组实验评价 | `cwru/evaluation/evaluate.py` | 加载最佳权重，对测试集预测，生成 `metrics.json`、`files.csv` 和单组实验图片 | “每一组训练完成后，都用同一个评价函数在测试集上生成指标和图。” | 保留 |
| 图表生成 | `cwru/evaluation/plots.py` | 生成损失曲线、验证曲线、混淆矩阵、模型对比、窗口方式对比、划分对比和最终结果总览 | “报告中的图都由实验结果自动生成，避免手工抄写数字。” | 保留 |
| 90 组结果汇总 | `cwru/evaluation/compare.py` | 读取 90 份 `metrics.json`，写出总表，计算 A/B/C 的平均值和标准差，并找出最佳分类与回归配置 | “最后不是看某一套划分，而是比较三套划分的平均表现和稳定性。” | 保留 |
| 单个文件预测 | `cwru/inference/predict.py` | 读取一个新的 MAT 文件，采用训练时相同的通道、窗口和标准化参数，输出故障类别与故障直径 | “这是答辩演示功能，用已有最佳模型对单个文件进行预测。” | 必须保留 |

### 2.2 应当新增的两个简单入口

复杂命令行删除后，仍然需要保留两个普通学生容易理解的入口文件。

| 内容 | 建议位置 | 具体作用 | 汇报时怎样解释 |
|---|---|---|---|
| 90 组实验主程序 | 项目根目录 `run_experiments.py` | 使用四层普通 `for` 循环，依次执行 3 套划分、2 种窗口、5 种输入和 3 个模型；每组调用训练和评价；最后调用结果汇总 | “3×2×5×3 等于 90，主程序就是按这四个维度循环。” |
| 单文件预测演示 | 项目根目录 `predict_one.py` | 文件顶部写明待预测文件、模型目录、输入方案和模型名称，然后调用单文件预测函数 | “答辩时只需修改文件路径和模型配置，再运行这个脚本。” |

`run_experiments.py` 不需要子命令、参数解析、批次类或自动 README。它只需要清楚展示下面这条流程：

```text
读取固定划分
    ↓
按输入方案构建数据
    ↓
训练模型并保存最佳权重
    ↓
在测试集上生成指标和图表
    ↓
汇总全部 90 组结果
```

### 2.3 建议删除的工程化代码

| 内容 | 当前所在位置 | 现在是做什么的 | 为什么不适合最终汇报版本 | 删除后的影响 |
|---|---|---|---|---|
| 统一命令行系统 | `cwru/cli.py` | 注册 `audit-data`、`split-init`、`prepare`、`train`、`full-run`、`evaluate`、`compare`、`predict` 等子命令 | 子命令、参数解析和路由更像正式软件，不是实验核心，汇报时也很难逐项解释 | 所有 `python -m cwru ...` 命令失效，由两个简单入口脚本代替 |
| 软件包命令入口 | `cwru/__main__.py` | 把 `python -m cwru` 转发到命令行系统 | 只服务于复杂命令行，删除命令行后没有作用 | 无实验影响 |
| 批次管理器 | `cwru/batch.py` | 创建批次目录、复制划分、写运行配置、不断更新大段 README 和结果表 | 代码很长，主要是管理文件，不涉及神经网络实验；自动记录 Git 版本和时间也不需要在汇报中解释 | 不再自动生成批次 README 和配置文件；现有结果不受影响 |
| 复杂批量编排器 | `cwru/fullrun.py` | 调用批次管理器并自动运行 90 组实验 | 与批次管理器耦合，逻辑可以用一个简单四层循环表示 | 由根目录 `run_experiments.py` 代替 |
| 独立数据准备命令 | `cwru/data/prepare.py` | 单独生成元数据、划分和实验清单 | 数据读取和划分已经会在实验主程序中完成，单独包装一层会增加理解成本 | 不再有独立 prepare 步骤；实验主程序直接构建数据 |
| Python 字节码缓存 | 所有 `__pycache__` 目录和 `.pyc` 文件 | Python 运行后自动产生的临时文件 | 不是源代码，会让目录显得杂乱 | 可以随时重新生成，没有功能影响 |

## 3. 现有 90 组结果怎样与最终代码对应

现有正式结果不是孤立文件。最终代码应当保留下面的对应关系：

| 结果内容 | 由哪部分代码产生 | 代表什么 | 汇报时怎样解释 |
|---|---|---|---|
| 每组目录中的最佳模型权重 | 模型训练过程 | 验证集总损失最低时的模型参数 | “不是使用最后一轮模型，而是保存验证集表现最好的一轮。” |
| 每组目录中的训练历史 | 模型训练过程 | 每个 epoch 的训练损失、验证损失、Accuracy、F1、MAE 和学习率 | “损失曲线和验证曲线都从这里生成。” |
| 每组目录中的汇总指标 | 单组实验评价 | 该组在测试集上的窗口级和文件级指标 | “90 组实验各有一份统一格式的测试结果。” |
| 每组目录中的逐文件预测表 | 单组实验评价 | 每个测试文件的真实类别、预测类别、类别概率和预测直径 | “文件级指标可以追溯到每个测试文件，而不是只有一个总数字。” |
| 每组目录中的图片 | 图表生成代码 | 损失曲线、混淆矩阵、分类和回归细分图 | “单组模型训练和测试情况由这些图表示。” |
| 汇总目录中的 90 组总表 | 90 组结果汇总代码 | 把全部 `metrics.json` 合并成一张表 | “所有模型比较都来自同一张90组总表。” |
| 汇总目录中的均值与标准差表 | 90 组结果汇总代码 | 同一配置在 A/B/C 三套划分下的平均值和波动 | “平均值表示总体效果，标准差表示结果对文件划分是否敏感。” |
| 汇总目录中的结论和对比图 | 90 组结果汇总与图表代码 | 最佳分类配置、最佳回归配置，以及模型、窗口、划分和输入方式的对比 | “报告结论由程序从90组指标中统一计算。” |

老师询问“这些结果怎么生成”时，可以按照下面五句话回答：

1. 数据处理代码读取 MAT 文件，先按固定文件名单划分训练、验证和测试集，再切成 1024 点窗口。
2. 模型代码建立 CNN、CNN-GRU 和 CNN-LSTM，并同时完成故障分类和直径预测。
3. 训练代码使用训练集更新参数，使用验证集选择最佳模型，并保存最佳权重和逐轮训练历史。
4. 评价代码加载最佳权重，在测试集上生成指标、逐文件结果和图片。
5. 实验主程序对 3 套划分、2 种窗口、5 种输入和 3 个模型循环执行，结果汇总代码最后读取 90 份指标计算均值、标准差和总体结论。

## 5. 单文件预测应该怎样与模型结果对应

单文件预测必须保留，并且应当直接使用最佳权重中保存的训练配置：

1. 根据输入方案选择 DE、FE 或双通道；
2. 按对应窗口长度和步长切分信号；
3. 从最佳模型文件中读取训练时的均值和标准差；
4. 使用相同的标准化方法处理新文件；
5. 对所有窗口预测；
6. 对窗口类别概率取平均，得到文件级类别；
7. 对故障窗口的直径预测取平均，得到文件级故障直径。

这样可以删除独立实验清单依赖，因为每个最佳模型已经保存了它自己的标准化参数。汇报时可以解释为：

> 预测新文件时必须使用训练模型当时的标准化参数，不能对新文件单独计算均值和标准差，否则训练和预测的数据尺度不一致。

## 6. 推荐的最终处理顺序

| 顺序 | 操作 | 完成标准 |
|---:|---|---|
| 1 | 新建简单的 `run_experiments.py` | 能清楚看到 3×2×5×3 的四层循环和训练、评价、汇总调用 |
| 2 | 新建简单的 `predict_one.py` | 修改顶部几个变量即可对一个 MAT 文件预测 |
| 3 | 简化固定划分读取 | 只读取现有 6 个 JSON，并检查 train/val/test 没有重叠 |
| 4 | 让单文件预测从最佳权重读取标准化参数 | 不再依赖独立 manifest 文件 |
| 5 | 删除命令行、批次管理、复杂完整运行器和独立 prepare | 最终代码只剩实验主线 |

| 8 | 删除旧版、单组和临时结果 | `artifacts` 中只保留正式 90 组结果和必要元数据 |
| 9 | 把正式结果目录整理为 `artifacts/final_results` | 目录名称与最终 README、预测脚本和报告一致 |

## 7. 建议保留与删除的最终结论

### 保留

- 数据识别、信号读取、降采样、切窗和标准化；
- 固定划分 JSON 和简单的划分读取检查；
- 三个神经网络；
- 分类和故障直径两个任务；
- 普通训练、验证集选最佳模型、学习率调度和早停；
- 单组评价、指标和图表；
- 90 组结果汇总；
- 单文件预测；
- 一个简单实验主程序和一个简单预测脚本；
- 90 个最佳权重、训练历史、测试指标、逐文件预测、图片和总体汇总。

### 删除

- 统一 CLI 和 `python -m cwru` 软件包入口；
- 批次上下文、动态 README、Git 版本和运行状态管理；
- 独立 prepare 命令；
- 复杂批量运行包装；
- manifest 依赖；
- 全部断点续训检查点；
- 旧版 10 组结果、临时验证结果和未引用的单组结果；
- 所有 Python 缓存。

这套方案不是单纯把文件删少，而是把项目收缩成一条能够完整说明现有 90 组结果的实验链条。
