## 四 问题一 文件级回归指标修正

### 4.1 问题范围

该错误发生在模型完成窗口预测之后的“文件级回归聚合”阶段，不是模型训练时把测试标签作为输入。

因此旧结果中：

- 窗口级分类指标有效。
- 窗口级回归指标有效。
- 文件级分类指标有效。
- 文件级回归 MAE 和 RMSE 无效。

### 4.2 当前错误逻辑

一个 MAT 文件被切成多个窗口。文件级直径应当由该文件所有窗口的模型预测取平均得到。

旧代码在聚合时使用了窗口真实直径 `y_reg`，相当于：

```text
真实标签：14、14、14
文件预测：(14 + 14 + 14) / 3 = 14
文件误差：|14 - 14| = 0
```

所以旧文件级 MAE 和 RMSE 必然为 0，与模型真实预测能力无关。

### 4.3 修正方案

1. 文件聚合函数增加模型连续直径预测参数。
2. 评估函数将模型输出的窗口直径预测传入文件聚合函数。
3. 对一个故障文件内所有窗口的模型预测取算术平均：

   ```text
   文件预测直径 = 该文件所有窗口预测直径之和 / 窗口数
   ```

4. 使用文件预测直径与文件真实直径计算文件级 MAE 和 RMSE。
5. 文件级回归指标保留连续数值，不吸附到 7、14、21、28 mil 四个档位。
6. Normal 文件不参与故障直径 MAE 和 RMSE。
7. 文件级分类仍使用窗口分类概率的平均值，不受本次修正影响。

### 4.4 精简验证方式

不为此问题新增专项自动测试文件。

代码修改后只做一次人工一致性核对：

1. 选择一个测试故障文件。
2. 读取该文件全部窗口的模型连续直径预测。
3. 人工计算预测均值。
4. 确认 `files.csv` 中的文件预测直径与人工均值一致。
5. 确认文件级 MAE 和 RMSE 不再全部为 0。

### 4.5 metrics 与 files 的去重

当前指标 JSON 中可能嵌入逐文件完整记录，与 CSV 重复。正式实现时调整为：

- `metrics.json`：只保存一组实验的汇总指标。
- `files.csv`：只保存逐测试文件预测记录。

两者不重复保存相同的逐文件明细。

## 五 问题二 三套平衡固定划分

### 5.1 旧划分的问题

旧划分先按照故障端、故障类别、直径和外圈位置排序分组，再根据全局剩余名额依次填充。

由于 Drive 文件排在前面，而训练集名额最大，造成大量 Drive 文件先进入训练集。101 文件公共故障中出现了 Drive 全部进入训练集、验证和测试主要由 Fan 构成的失衡现象。

问题根源不是随机种子，而是“排序后按全局名额填充”的分配逻辑。

### 5.2 新划分的基本原则

使用经过人工核验的固定文件名单定义 A、B、C 三套划分。固定名单直接保存在 `cwru/data/split.py`，保存后的 JSON 用于训练读取和批次快照。代码不再保留划分随机种子、候选数量或运行时搜索实现。

### 5.3 数量硬约束

每套 101 文件划分必须严格为：

```text
训练：71
验证：15
测试：15
```

每套 109 文件划分必须严格为：

```text
训练：75
验证：17
测试：17
```

101 和 109 的公共文件在同一套划分中的归属必须完全一致。

109 文件方案额外加入 B028 和 IR028：

- B028：训练 2、验证 1、测试 1
- IR028：训练 2、验证 1、测试 1

### 5.4 单套划分的平衡目标

每套划分都必须在训练、验证和测试中尽量覆盖并平衡：

- 测量端：Drive、Fan
- 故障类别：Normal、IR、OR、B
- 故障直径：7、14、21 mil；109 方案另含 28 mil
- 负载：0、1、2、3
- 外圈故障位置：3、6、12 点钟

由于部分细分组合样本数量很少，无法保证所有属性都精确达到 70%/15%/15%。实现时优先级为：

1. 文件数量和集合无交叉必须严格满足。
2. Drive/Fan 与故障类别覆盖必须满足。
3. 直径分布尽量平衡。
4. 负载和外圈位置尽量平衡。

### 5.5 三套划分之间的差异目标

A、B、C 不应只是名称不同，而应尽量覆盖不同的验证和测试文件。

固定名单满足以下目标：

- 三套测试文件尽量不重复。
- 三套验证文件尽量不重复。
- 尽量让更多原始文件至少在一套中进入测试集。
- 在减少划分间重复的同时，不能破坏单套划分的平衡要求。

Normal 和 28 mil 文件数量较少，每套内部仍固定采用 2/1/1；三套 109 测试集保持完全不重复。

### 5.6 划分生成物

三套划分固定保存在项目的正式配置区域，并在每个新批次中复制一份快照：

```text
splits/
├── A/
│   ├── split_101.json
│   ├── split_109.json
│   └── README.md
```

划分 README 说明固定名单来源、约束、实际分布和稀有组合；类别和条件统计在运行时由原始 MAT 文件审计结果计算，不额外保存汇总 CSV。

### 5.7 划分验收

- 101 每套严格为 71/15/15。
- 109 每套严格为 75/17/17。
- 训练、验证、测试文件无交叉。
- 101/109 公共文件归属一致。
- 三个集合均包含 Drive 和 Fan。
- 三个集合均覆盖主要故障类别。
- 同一固定划分被所有模型和窗口方案共同使用。
- A、B、C 的测试文件重复率达到约束下的最低或合理水平。

## 六 CNN LSTM 模型扩展

### 6.1 公平比较原则

新增模型命名为 `CnnLstm`，与 `CnnGru` 使用相同 CNN 主干、相同隐藏规模和相同输出头。

结构建议：

- CNN 卷积主干与现有模型完全一致。
- 单层双向 LSTM。
- 单方向隐藏维度 64。
- 拼接双向最终隐藏状态，得到 128 维共享特征。
- 分类头输出 Normal、IR、OR、B 四分类 logits。
- 回归头输出连续故障直径缩放值。

保持以下训练条件一致：

- 损失函数
- 分类权重
- 回归掩码
- 优化器
- 学习率
- 权重衰减
- Batch Size
- 最大 epoch
- 早停规则
- 学习率调度
- 训练种子

模型之间的主要变量应当是 CNN、GRU 和 LSTM 的时序结构差异。

### 6.2 训练种子

三套文件划分衡量的是模型对不同文件划分的敏感程度，不再叠加多组模型初始化种子。

正式 90 组统一使用：

```text
TRAIN_SEED = 42
```

最终平均值和标准差表示划分 A/B/C 的结果波动，不宣称为模型初始化方差。

## 七 50% 重叠窗口

### 7.1 定义

无重叠方案：

```text
window_len = 1024
stride = 1024
overlap = 0%
```

50% 重叠方案：

```text
window_len = 1024
stride = 512
overlap = 50%
```

### 7.2 数据安全原则

必须先按 MAT 文件划分训练、验证和测试集，再分别在各集合内部切窗口。

同一原始文件的窗口禁止跨集合出现。50% 重叠只发生在同一个文件内部，因此不会造成训练集和测试集之间的窗口泄漏。

### 7.3 报告解释

50% 重叠会使窗口数量接近翻倍，但相邻窗口共享 512 个采样点，因此新增窗口并不等于同等数量的独立新信息。

正式比较应在相同文件划分、相同输入方案、相同模型和相同训练参数下，只改变 stride。

## 十五 风险与注意事项

1. **划分稀疏性**：Normal 和 28 mil 文件很少，三套划分无法做到所有属性完全独立，应在划分 README 中诚实说明。
2. **重叠窗口相关性**：50% 重叠增加样本数但也增加相邻窗口相关性，不能把窗口翻倍表述为独立数据翻倍。
3. **三套划分统计含义**：A/B/C 的标准差反映文件划分敏感性，不代表多训练种子方差。
4. **过拟合**：已经观察到训练损失接近 0、验证损失波动，但本轮按用户决定暂不处理。
5. **本地旧归档**：旧归档不推送仓库，应避免在后续 Git 操作中误提交。
6. **缓存复用**：公共缓存必须包含窗口步长、输入方案、固定划分及归一化信息，避免无重叠和 50% 重叠之间误用缓存。
7. **正式结果完整性**：任何检查或临时验证都不得写入正式批次的模型目录。
8. **中断策略**：本计划不实现断点状态系统；如发生中断，保留不完整目录作为记录，再新建批次重跑。
